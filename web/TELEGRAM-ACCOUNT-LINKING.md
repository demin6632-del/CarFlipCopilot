# AUTOFLIP — безопасная привязка Telegram-аккаунта к игровому профилю

Статус: основа привязки, endpoint выдачи challenge и обработчик `/link` подготовлены в отдельных Draft PR. Интеграция **не включена и не развёрнута**; миграции не применялись к Neon.

## Модель идентичности

- Игровые профили хранятся в `autonomous_game_state` с ключом `chat_id`.
- Telegram update содержит `message.from.id` (пользователь) и `message.chat.id` (чат). Это разные идентификаторы и код не предполагает, что они совпадают.
- `load(chat, firstName)` не является read-only: может создать/нормализовать профиль и синхронизировать реестр номеров. Его нельзя вызывать из GET сайта.
- Подписанный Mini App `initData` подтверждает Telegram user ID, но само по себе не доказывает владение игровым профилем.

## Подготовленный сценарий

1. Mini App отправляет подписанный Telegram `initData` на `POST /api/web/link-challenge` с точным разрешённым Origin.
2. Сервер проверяет подпись и свежесть `initData`, затем создаёт 128-битный одноразовый код. Код возвращается только в ответе этому Mini App-сеансу; в PostgreSQL хранится только SHA-256 digest.
3. Код действует пять минут. Выпуск ограничен пятью кодами в час на Telegram user ID; новый код инвалидирует предыдущий активный.
4. Пользователь открывает личный чат с AUTOFLIP и отправляет `/link КОД`.
5. Обработчик бота требует `chat.type === "private"`, берёт `message.from.id` и `message.chat.id` непосредственно из Telegram update и передаёт их сервису подтверждения.
6. Сервис в одной транзакции блокирует challenge, проверяет владельца и срок действия, создаёт уникальную связь и помечает код использованным.
7. После успешной привязки Mini App может запросить `POST /api/web/session`; серверная сессия использует HttpOnly cookie и хранит в БД только SHA-256 хеш токена.

## Защитные ограничения

- `/link` появляется в меню бота и выполняется только при явном `AUTOFLIP_ACCOUNT_LINKING_ENABLED=true`. По умолчанию флаг выключен.
- При выключенном флаге обработчик не открывает соединение с базой.
- Коды не выводятся в логах и не повторяются в ответах бота.
- Нельзя принимать `chat_id`, user ID или владельца из браузерного тела запроса.
- Уникальные ограничения не позволяют связать один Telegram user ID или private chat ID с несколькими аккаунтами.
- Нельзя перезаписывать существующую привязку автоматически; конфликт требует отдельной процедуры поддержки.
- Web API остаётся отдельным процессом и не подключается к небезопасным маршрутам legacy relay.

## Проверки и состояние

- Сервис challenge имеет unit- и PostgreSQL integration tests для срока действия, повторного использования, несовпадения владельца, гонок, уникальности, rollback и rate limit.
- Для endpoint выдачи кода и обработчика `/link` добавлены unit tests.
- CI для текущих изменений ещё должен подтвердить все новые проверки.
- Миграции `telegram-account-linking.sql` и `web-account-sessions.sql` не применялись к Neon или production.
- Mini App frontend пока не вызывает endpoint; полный end-to-end сценарий не проверен на отдельной тестовой среде.
- Render API не создан и не развёрнут; live Telegram-бот не менялся.
