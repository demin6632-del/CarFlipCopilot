# AUTOFLIP — безопасная привязка Telegram-аккаунта к игровому профилю

Статус: изолированная основа сервиса и миграция подготовлены; обработчик бота, API, сессии и применение миграции **не подключены**.

## Что подтверждено аудитом

- Игровые профили хранятся в `autonomous_game_state` с ключом `chat_id`.
- Входящее сообщение содержит `message.from.id` (пользователь) и `message.chat.id` (чат), но текущая игра использует chat ID.
- `load(chat, firstName)` не является read-only: может создать и нормализовать профиль и синхронизировать реестр номеров. Его нельзя вызывать из GET сайта.
- Проверка Mini App `initData` подтверждает Telegram user ID, но не доказывает владение конкретным игровым профилем.

## Что добавлено в этой ветке

- `relay/telegram-account-linking.js`: изолированный сервис выпуска и подтверждения одноразовых кодов.
- `relay/telegram-account-linking.sql`: аддитивная миграция двух таблиц.
- `relay/telegram-account-linking.test.js`: тесты нормализации, хеширования, выпуска кода, приватного чата, транзакционных границ и отказа при несовпадении Telegram user ID.
- Скрипт тестов добавлен в общий `npm test`.

Сервис выпускает 128-битный случайный код (32 hex-символа), сохраняет только SHA-256 digest, ограничивает выпуск пятью кодами в час на Telegram user ID, использует TTL по умолчанию пять минут и инвалидирует предыдущий активный код при выпуске нового. Идентификаторы сохраняются как text, чтобы не зависеть от ограничений JS Number для BIGINT.

Подтверждение требует `chatType === "private"`, точного совпадения Telegram user ID, незавершённого challenge и срока действия по часам PostgreSQL. Создание связи и отметка challenge как использованного выполняются в одной транзакции. Уникальные ограничения защищают обе стороны связи. Advisory transaction lock сериализует операции одного Telegram user ID.

## Что пока не сделано

- Миграция не применялась к preview или production. Relay CI применяет её дважды к одноразовой PostgreSQL 16 базе, чтобы проверить создание схемы и повторный запуск.
- Сервис пока не вызывается из Telegram-бота или HTTP API.
- Команда `/link` не зарегистрирована и не подключена.
- Mini App не выдаёт код и не создаёт сессию.
- Не реализованы session store, CSRF и read-only API.
- Для endpoint/бота ещё потребуются ограничения частоты попыток подтверждения, безопасные ответы и аудит; сам код имеет 128 бит энтропии.
- Не добавлены PostgreSQL integration tests с реальной БД; текущие unit tests используют контролируемый fake client.
